# F004 — Session-end Markdown report

## Problem definition

F010 persists a per-session Session JSONL log (mapped by F003) so later reporting can read one sequential file without scanning the Event log. That JSONL is complete for a machine, but it is not a session summary a developer can skim: there is no duration, no count by event kind, and no readable table of what happened.

Developers need ingest, on the same invocation that appends a Session JSONL log record, to also write a single Markdown report for that session in the same daily folder. The report is derived only from that session’s Session JSONL log. This spec does not replace F001–F003, F005–F007, F008, or F010. Event log verbatim rules, Session index rules, Session JSONL log append-only and format rules, observe-only exit/stdout, and Cursor hook registrations stay with those specs.

This amend (C001 / F010) changes only the report’s source file: produce `{session_id}.md` from that session’s Session JSONL log (all records, file order, no re-sort). An ingest must **not read** `events.jsonl` or `sessions.json` to build it. Duration, counts, turn grouping, Subagent cell, and 100-character previews stay as they are. F003 still owns mapping. Markdown `{session_id}.md` is unchanged.

This amend (F009) fills the Subagent cell with **only the `subagent` value** (the name) whenever that field is present on the JSONL record — any event kind, not only start/stop — with no field-name prefix (`agent_type:`, `subagent:`, `agent_display_name:`, or similar). `agent_display_name` stays in the Session JSONL log per F007 when Copilot sends it and stays out of Details; it is not shown in the Subagent cell. Identity is not copied onto later rows that omit it. Parent→subagent hierarchy stays out of scope. Persistence of `subagent` on every event is F003 / F009; this spec does not duplicate those ACs. AC-F004.20 (prefixed `{name}: {value}` pairs on start/stop only) is retired.

This amend drops the session-end gate. A Session report must still be produced when `sessionEnd` never arrives (the session ended abruptly). Duration stays elapsed clock time from the first JSONL record’s `timestamp` to the last, whatever those events are — not Cursor `duration_ms` and not a session-end-only field. Overview `harness` comes from the last record (the ingest that just ran). The Session JSONL log already persists `subagent`, `agent_display_name`, `task`, and `response_text` (F009 / F007 / F006 mapping; F003 omits absent fields).

This amend (F008’s report consumer) groups the chronological event list by conversation turn. Each JSONL record carries integer `turn` (F003 / F008). A single flat Events table hides turn boundaries: agent-stop and subagent-stop can fire many times during one prompt, so pairing a prompt with the next stop undercounts that turn. The report reads `turn` from the Session JSONL log, shows a subsection per turn that appears, and computes each turn’s duration from that turn’s prompt (or from the first turn-0 record) to the last record of that turn. Session overview duration stays first→last record (session-level). Event-count summary stays session-level. How `turn` is numbered stays F008; this spec does not duplicate those ACs.

This amend (released 0.13.0) adds a Subagent column so subagent identity is not packed into Details. Each per-turn event table has four columns, in this order: Time, Event, Subagent, Details. Subagent is optional: it is filled whenever that JSONL record has `subagent`, as the bare name only (F009; AC-F004.24), and is empty when that field is absent. Details must not repeat `subagent` or `agent_display_name`. Preview length is 100 characters (first 100 + `...`) for Details cells, Subagent cells, and the per-turn prompt line. Parent→subagent hierarchy stays out of scope (`agent_id` is not in the Session JSONL log). Persistence of `subagent` on every event is F003 / F009; this spec is the report consumer.

This amend follows F003 compact headers. Report labels use JSONL `harness` and `event` (not `source_harness` / `source_event`). Overview `session_id` is always the F001 identifier (filename stem); the report must not require `session_id` on every JSONL record. When the first record has `session_id`, it matches; when omitted, the report still shows the F001 identifier. Overview `harness` is the last record’s `harness`. Event-count and the Event column use `event`. Migrating or reading mixed historical YAML that still has `source_harness` / `source_event` / per-document `session_id` is out of scope.

Normalized body fields per event kind are those in [`docs/normalized-fields.md`](../../normalized-fields.md). Event-kind names across harnesses are those in [`docs/events-args.md`](../../events-args.md).

This amend (C002) makes the report the consumer of newly normalized Codex data. A Codex record uses the same PascalCase event names as Claude Code; it remains an ordinary row in its existing turn subsection. Details render the normalized native values that are present: `model`, `permission_mode`, `source`, and `cwd` on session start; `cwd` on session end and user prompt; `agent_id` on subagent start and stop; `response_text` on subagent stop and agent stop; and the existing `reason` and `prompt` where Codex supplies them. `turn_id` remains F008’s source for the header `turn`, rather than a duplicate Details value. The Subagent cell remains only the normalized `subagent` name; `agent_id` appears in Details so the matching Codex start/stop rows can be correlated. `transcript_path` remains excluded by F005. Fields not normalized by C002 remain in the verbatim Event log and are not invented in the report.

### User Stories

- As a developer, I want **a Markdown report after each ingested session event** so that I can read what happened even when the session ends abruptly and `sessionEnd` never fires.
- As a developer, I want **overview, counts, and events grouped by conversation turn** so that I can see session duration, mix of event kinds, and a short line per event inside each turn.
- As a developer, I want **each turn’s duration from that turn’s prompt to its last event** so that repeated agent-stop events in a loop do not undercount the turn.
- As a developer, I want **duration from the first event’s time to the last** so that the session overview stays valid regardless of which event kinds are in the file.
- As a developer, I want **a Subagent column on each per-turn event table** so that I can see the subagent name when that record persisted it, as the name only, without packing identity into Details.
- As a developer, I want **the report built only from that session’s Session JSONL log** so that the normalized log remains the single source and the Event log stays the verbatim archive.
- As a developer, I want **report labels `harness` and `event` matching the JSONL keys** so that overview, counts, and the Event column stay aligned with the compact header.
- As a developer, I want **overview `session_id` from the F001 identifier** so that the report still names the session when JSONL omits `session_id` on later records.
- As a developer, I want **long prompts, responses, tasks, and display names trimmed at 100 characters** so that the report stays scannable; full text remains in the Event log.
- As a developer, I want **the report from the same observe-only ingest invocation** so that I do not run a second command.
- As a developer, I want **Codex-native session, workspace, subagent-correlation, and final-message details in the report when normalized** so that the report preserves useful hook context without reading raw payloads.

### Business Rules

- An ingest must **still persist as F001 and F010/F003** (verbatim Event log, Session index, Session JSONL log append, daily folder, observe-only exit 0 and no blocking stdout) on every invocation, including those that also write a Session report.
- A Session report is always **a `.md` file** named `{session_id}.md` inside that day’s folder, where `{session_id}` is the F001 session identifier already used for the Session JSONL log.
- An ingest must **write a Session report whenever** it appends a Session JSONL log record (the payload has a session identifier), after that record is in that session’s Session JSONL log — no second process, and no new user-facing report command. An ingest must **not require** the F002 `event` positional to be session-end (`sessionEnd` / `SessionEnd`). An ingest must **not infer** the report trigger from the Event log payload.
- A Session report must **still be produced** when no session-end record is in that file.
- A Session report must **be produced only from** that session’s Session JSONL log (every record, in file order). An ingest must **not read** the Event log (`events.jsonl`) or the Session index (`sessions.json`) to produce it. The report must **read** `turn` from each JSONL record (F008).
- When an event has **no session identifier**, F010 writes no Session JSONL log, and an ingest must **not create** a Session report.
- When a later ingest appends another JSONL record for the **same session the same day**, an ingest must **overwrite** `{session_id}.md` from the Session JSONL log as it then stands. An ingest must **not append** a second report in that file.
- A Session report is always **Markdown with tables, never HTML**.
- A Session report must **include a session overview** with: `session_id` (always the F001 identifier / filename stem already used for that session); `harness` from the last record (the ingest that just ran); start time (first record’s `timestamp`); end time (last record’s `timestamp`); and total duration. Overview `session_id` must **not require** `session_id` on every JSONL record. When the first record has `session_id`, it matches; when omitted, the overview must **still show** the F001 identifier. `harness` must **not** be taken only from a session-end record.
- Start time, end time, and duration are always **from the records in that day’s Session JSONL log** (the folder’s calendar day). They must **not** be reconstructed across days.
- Session duration is always **elapsed clock time** from the first JSONL record’s `timestamp` to the last JSONL record’s `timestamp` in that file, regardless of those records’ `event`, displayed as zero-padded `HH:MM:SS`. An ingest must **not** use Cursor `duration_ms` or any session-end-only field for duration. When the last timestamp is **before** the first, duration must **be `00:00:00`**. When they are equal, duration must **be `00:00:00`**.
- A Session report must **include an event-count summary**: the number of JSONL records, and a breakdown of how many records have each distinct `event` value (session-level, not per-turn). The table header must **be `event`**.
- A Session report must **not** use a single session-wide Events table. It must **include one Markdown subsection per distinct `turn` value** that appears in the Session JSONL log, in ascending turn-number order. Each subsection must **show** that turn number, that turn’s duration, and (for turns ≥ 1) that turn’s prompt text. Each subsection must **then** include a Markdown table of that turn’s records in file order (no re-sorting), with four columns in this order: Time (`timestamp`), Event (`event`), Subagent (the `subagent` value when present, optional), and Details (remaining normalized body fields). An ingest must **not nest** subagents.
- When the Session JSONL log has **no** records with `turn` 0, the report must **omit** a turn-0 subsection. It must **not** invent an empty turn 0.
- Turn duration is always **elapsed clock time** displayed as zero-padded `HH:MM:SS`, with the same last-before-first → `00:00:00` and equal → `00:00:00` rules as session duration. For turn **n ≥ 1**, start is always **that turn’s prompt-kind record `timestamp`**; end is always **the last record in the file that has `turn: n`**. For turn **0**, start is always **the first record with `turn: 0`**; end is always **the last record with `turn: 0`**. An ingest must **not** close a turn on `stop` / `agentStop` / `Stop` / `subagentStop` / `SubagentStop`. Those events belong to whichever turn is current; their multiplicity does not start or end a turn.
- For a turn **≥ 1**, the subsection must **include** the prompt text from that turn’s prompt-kind record, using the same 100-character single-line preview rules as Details and Subagent. When `prompt` is absent from that record, the prompt line must **be omitted**. A turn-0 subsection must **not** include a prompt line.
- A Subagent cell may **include only** that record’s `subagent` value (the name), with no field-name prefix (`agent_type:`, `subagent:`, `agent_display_name:`, or similar). Present values including JSON `null` appear as that value. A Subagent cell must **be filled whenever** that record has `subagent`, for any event kind. When `subagent` is **absent**, Subagent must **be empty**. `agent_display_name` must **not** appear in the Subagent cell (it stays in the Session JSONL log per F007 when Copilot sends it). An ingest must **not** reconstruct parent→subagent hierarchy. An ingest must **not** copy `subagent` onto later records that omit it.
- Details may **include only** the remaining normalized body fields for that event kind in [`docs/normalized-fields.md`](../../normalized-fields.md), excluding `session_id` (already in the overview), `subagent` (the bare name belongs in the Subagent cell), and `agent_display_name` (not shown), using those snake_case names in table order and omitting fields absent from the record. Present values including JSON `null` appear. Multiple present fields in one cell are `{name}: {value}` pairs in table order, separated by `; `. A normalized `agent_id` is a Details field, not a Subagent-cell fallback.
- Event kinds for that Details mapping are: session start (`sessionStart` / `SessionStart`) — Codex `model`, `permission_mode`, `source`, and `cwd` when present; session end (`sessionEnd` / `SessionEnd`) — `reason` and Codex `cwd` when present; subagent start (`subagentStart` / `SubagentStart`) — `task` and Codex `agent_id` when present; subagent stop (`subagentStop` / `SubagentStop`) — `response_text` and Codex `agent_id` when present; user prompt (`beforeSubmitPrompt` / `userPromptSubmitted` / `UserPromptSubmit`) — `prompt` and Codex `cwd` when present; agent stop (`stop` / `agentStop` / `Stop`) — Codex `response_text` when present. A record lists only its normalized fields: absent fields, including Codex `task` (which it does not provide) and fields unsupported by another harness, are omitted. `turn_id` is not a Details field because F008 consumes it as `turn`; `transcript_path` stays excluded (F005). When the record is header-only (F003 unmapped harness or event), Details must **be empty** (`subagent` when present is the Subagent cell, not Details). Cursor and Claude Code have no `agent_display_name` (F007); Copilot persists it in the Session JSONL log when present and it stays out of Details and out of the Subagent cell.
- A Details cell, Subagent cell, or per-turn prompt line longer than **100 characters** must **appear as the first 100 characters followed by an ellipsis** (`...`). A value of 100 characters or fewer must **not** receive an ellipsis. A preview is always **a single line** (newlines in the source value are spaces before the limit is applied).
- A Session report must **list subagent start and stop as ordinary chronological rows** inside that turn’s table. It must **not nest** a subagent under a parent, and must **not** nest further inside a turn.
- A table cell must **remain one cell** even when a field value contains `|`, newlines, or other Markdown-significant characters.
- An ingest must **not register** new Cursor, Copilot, or Claude hooks (registrations are F001 / F005 / F006).
- An ingest must **not change** F001 Event log or Session index rules, F003 mapping rules, or F010 Session JSONL log append-only rules, except that this invocation may **read** the Session JSONL log after the record just appended is present (including each record’s `turn`) in order to write the report.
- When Session report generation **fails**, an ingest must **still persist as F001 and F010/F003**, must **still exit 0**, and must **not write blocking stdout**.
- An ingest must **run as Node.js ≥ 24 ESM with no external dependencies**, including no YAML library and no JSON library (platform `JSON.parse` is allowed). The report must **accept** the Session JSONL log as F010 writes it (one JSON object per line). An ingest must **not migrate or rewrite** old `{session_id}.yaml` session logs. New records use compact header keys. Reading mixed historical YAML is out of scope.

### Out of scope

- Reconstructing parent→subagent hierarchy or nesting subagents under a parent (`agent_id` is not in the Session JSONL log). An ingest must **not** copy `subagent` onto later records that omit it.
- Reports built from the Event log (`events.jsonl`) or the Session index (`sessions.json`).
- Dashboards, query commands, or any user-facing CLI command other than the existing ingest invocation.
- Changing F001 Event log verbatim rules, Session index rules, daily-folder naming, or observe-only exit/stdout.
- Changing F003 mapping, omit-absent / present-null, or [`docs/normalized-fields.md`](../../normalized-fields.md). Changing F010 format, filename, or serialization. Reading `turn` from the F003 header (F008) and grouping the event list by turn are in scope for this spec as F008’s report consumer. The Session JSONL log already has `subagent`, `agent_display_name`, `task`, and `response_text`; this spec only changes how the report displays them (F009: Subagent cell is the bare `subagent` value). Report labels follow JSONL `harness` / `event`.
- Defining Codex field extraction, normalized-field-table source keys, native `turn_id` conversion, or native `agent_id` persistence (F003, F008, F009, and F010); this spec only renders their normalized Session JSONL values.
- Duplicating F010 format ACs, F003 mapping ACs, or F008 turn-numbering ACs.
- Migrating or rewriting old `{session_id}.yaml` session logs, or YAML that still has `source_harness` / `source_event` / per-document `session_id`. Reading mixed historical files.
- Closing a turn on a stop or subagent-stop event.
- A Turn column instead of per-turn subsections.
- Per-turn event-count summaries (counts stay session-level).
- Registering GitHub Copilot or Claude Code hooks, or any Cursor hook (F006 registers `stop`; F005 already registered `beforeSubmitPrompt`).
- HTML reports, PII redaction, or transforming stored Event log / Session JSONL log content.
- Multi-day session reconstruction (overview times are this file / this calendar day only).
- Deleting or rotating older daily folders.
- Blocking, denying, or rewriting the agent.

## Solution overview

### Data Model

From [`model.schema.md`](../../model/model.schema.md): a **Session** is a related set of events; an **Event** is one hook payload; a **Session JSONL log** is the per-session append-only file of normalized JSON objects (F010), mapped by F003, each with integer `turn` (F008).

This feature adds a fourth daily artifact:

- **Event log** — JSONL; each line is one Event, verbatim (F001).
- **Session index** — JSON array of distinct session identifiers for that day (F001).
- **Session JSONL log** — one `{session_id}.jsonl` per distinct F001 session identifier (F010).
- **Session report** — one `{session_id}.md` per session that received a Session JSONL log record that day; Markdown; overwritten on every later Session JSONL log append for that session the same day; events grouped by `turn`; each per-turn table has Time, Event, Subagent, and Details, including normalized Codex-native Details values when present.

All four artifacts live in the same folder named for the current date.

### CLI

Per [`system.arch.md`](../../arch/system.arch.md) and [`cli.arch.md`](../../arch/cli.arch.md):

- On an ingest invocation that appends a Session JSONL log record (payload has a session identifier), after that record is in the file, write `{session_id}.md` in the same daily folder from that Session JSONL log alone — including when no session-end record is present. Do not read `events.jsonl` or `sessions.json`.
- Include overview (`session_id` from the F001 identifier / filename stem, `harness` from the last record, start, end, duration `HH:MM:SS` from first→last timestamps regardless of `event`), counts by `event` (session-level), and one Markdown subsection per turn that appears (turn number, duration, prompt preview for turns ≥ 1, then a flat Time / Event / Subagent / Details table of that turn’s records in file order; Event is JSONL `event`; Subagent is the bare `subagent` value when that record has the field; Details renders remaining normalized values including Codex-native fields when present; previews truncated at 100 characters with `...`).
- Overwrite the Markdown file when another Session JSONL log record for that session arrives the same day; skip the report when there is no session identifier.
- Remain a single Node.js ≥ 24 ESM ingest with no external dependencies (no YAML library and no JSON library; platform `JSON.parse` is allowed), observe-only (exit 0, no blocking stdout), including when report generation fails. Do not add a report command or new hook registrations.
